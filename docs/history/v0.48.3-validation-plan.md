# v0.48.3 validation plan — OTel gen_ai continuity

For whoever QAs `5789218` (PR #1041) on a non-production server. Everything below is observable; nothing asks you to trust the implementation.

The single most valuable outcome is **falsifying the central design bet** (phase 3). If that bet is wrong, cost accounting in Langfuse is wrong, and that matters more than any feature in this release.

## Before you start

- Deploy the pinned `0.48.3` image to the **non-production** server. Do not test on prod.
- Have a Langfuse instance reachable, with `observability.otel.otlp_endpoint` pointed at it.
- Note the current values of `observability.otel.*` in the deployed `quack.yaml` — phase 1 requires them unchanged.
- Grab a baseline: run one multi-node chat on v0.48.2 first and screenshot the Langfuse trace. Several phases are "compare against before".

## Phase 1 — the default posture is unchanged (regression gate)

Deploy with **no config change at all**. This is the state most deployments will be in.

1. Run a chat that produces a multi-node DAG (something that decomposes — a research question with a synthesis step).
2. In Langfuse, open the trace.

Expected:
- Generations still show model, token counts and cost, exactly as on v0.48.2.
- Input and output are **null**. Content capture is off by default; if you see prompts here, the gate has failed and that is a **stop-the-release** finding.
- No `trace` link renders on any node card in the UI (no template configured).
- Node cards, timings and judge scores look identical to v0.48.2.

Failure here means the release changes behaviour for people who changed no config. That is the one outcome this design was built to avoid.

## Phase 2 — the bug fixes, all UI-observable

None of these need Langfuse.

**2a. Queued revise round is labelled correctly.** Force a node to fail its judge and be revised while the DAG is at concurrency capacity (so the round gets queued and its run id picks up the `-s{N}` suffix). Before this release, that round appeared as a *worker* card at round 0. It should now appear as a **revise** card with its real round number.

**2b. Retry does not show a stale trace link.** Requires phase 4's template set, so do it after. Run a node to completion, note its `trace` link target, then retry that node. The link must point at the **new** run's trace, not the old one. A link that still resolves to the first execution is the exact bug this release fixed and means it regressed.

**2c. `started_at` survives completion.** This is the gorm `Omit` fix and it is easy to miss. Let a node run to `done`, then reload the chat from the API (`GET /api/v1/chats/{id}`) and confirm the node's start time is still populated. Before this fix, a `node_done` upsert blanked `started_at` and `instance_id`. Also worth checking after a server restart with a resumed node, which is where `instance_id` matters.

**2d. Compaction.** Drive a node long enough to trigger history compaction (a tool-heavy run against a small context window). The UI should show its compaction indicator as before; in Langfuse there should be a `quack.compaction` span carrying `gen_ai.conversation.compacted=true`. Known limitation: that span is a **disconnected trace root**, so it appears as its own tiny trace rather than nested in the run. That is expected, not a bug — filter by `gen_ai.conversation.id` to tie it back.

## Phase 3 — the central bet: no duplicate generations, no double-counted cost

**This is the phase that matters most.** The whole design rests on decorating ADK's existing generation span rather than creating a second one. If a second model-attributed span exists, Langfuse types it as a GENERATION too and cost is counted twice.

1. Run a chat with exactly **one** model call in one node, if you can arrange it (a trivial single-node question).
2. In Langfuse, count the GENERATIONs in that trace.

Expected: exactly **one** GENERATION per actual model call. Not two.

3. Compare the trace's total cost against the same prompt run on v0.48.2. It must be the **same**, not double.
4. Check that no `quack.*` span (node, worker.round, gate.judge, gate.revise, acp.tool.*, compaction) is typed as a GENERATION. They should all be plain spans.

If you see two GENERATIONs per call, or cost roughly doubled, stop and report — the fix is that some span gained a model-named attribute, and Langfuse promotes any such span.

**Also in this phase, the one genuinely unverified claim in the release:** the generation span now carries `gen_ai.agent.name`. Nobody has confirmed how Langfuse treats that attribute. Check specifically that adding it did **not** change the observation's type, its model name, or its cost attribution. If it did, the fix is renaming that attribute to `quack.agent` — report it rather than working around it.

## Phase 4 — the trace deep link

Set `observability.otel.trace_url_template` to your Langfuse trace URL with a literal `{trace_id}` placeholder, e.g. `https://langfuse.example.com/project/<id>/traces/{trace_id}`. Restart.

1. A `run trace` link appears on each node card.
2. Clicking it opens the correct trace for that run.
3. The label says "run trace", not "trace" — it is deliberately **trace-level**, not per-node. Every node on a run links to the same trace. That is expected.
4. Reload the page mid-run and after completion: the link survives (it is persisted on the node).
5. Unset the template and restart: the link disappears entirely — no dead icon, no disabled stub.
6. Try setting the template to something that is not `http(s)://`. The server must **refuse to start** with a clear config error. If it boots and renders a link, the scheme guard failed.

Then do **2b** above.

## Phase 5 — content capture, deliberately and carefully

Set `observability.otel.capture_content: true`. Restart.

Understand what you are turning on: this ships user prompts and model responses to the OTLP endpoint. Do it on non-prod, with a prompt you are happy to have stored.

1. Run a chat. Langfuse generations should now show input and output.
2. **Redaction:** include a secret under a matching key in your prompt — something JSON-shaped like `{"api_key": "sk-test-12345"}`. In Langfuse it must render as `[REDACTED]`.
3. **Known limitation, confirm it rather than being surprised by it:** a secret in *prose* (`my api key is sk-test-12345`) will **not** be redacted. Redaction is key-name matching only. Verify this is the behaviour so it is documented rather than discovered later.
4. **Truncation:** send a prompt well over 8 KiB. The span attribute should be truncated with a `…[truncated]` marker. Note that the UI shows the full text — UI and Langfuse legitimately differ above 8 KiB.
5. **ACP tool calls:** run a coding agent (code-implementer or code-reviewer) so the ACP path fires. Its tool-call arguments and results should now appear on the tool spans — and must be **absent** when you set the flag back to false. Both sites matter; an earlier version of this change gated only one of them.
6. Set the flag back to false, restart, confirm content stops appearing.

## Phase 6 — node correlation

With a multi-node run in Langfuse, confirm generations carry `quack.node` and `gen_ai.agent.name`, and that you can filter the trace down to a single node with them. This is the difference between "the trace exists" and "the trace answers which node did what".

Edge case worth one try: node ids come from the orchestrator's plan and are only exported when slug-shaped. If you ever see a node whose id is a long sentence, its `quack.node` attribute should be **absent** rather than exported — that guard is deliberate.

## Phase 7 — dashboards (do this before anyone relies on them)

Seven metric labels were renamed. Any saved Grafana query filtering on the old label goes **blank rather than erroring**, which is why this needs an explicit check.

| Metric | Old label | New label |
|---|---|---|
| `quack.worker.round.duration` | `agent`, `model` | `gen_ai.agent.name`, `gen_ai.request.model` |
| `quack.judge.score` | `agent` | `gen_ai.agent.name` |
| `quack.judge.verdict` | `agent` | `gen_ai.agent.name` |
| `quack.judge.unavailable` | `agent` | `gen_ai.agent.name` |
| `quack.acp.permission_ask` | `agent` | `gen_ai.agent.name` |
| `quack.memory.commit.failures` | `agent` | `gen_ai.agent.name` |
| `quack.model.call.duration` | `model` | `gen_ai.request.model` |

`gen_ai.client.token.usage` and `gen_ai.client.cost` keep the bare `agent` label — unchanged on purpose.

Also: `acp.prompt`'s `stop_reason` span attribute is now `gen_ai.response.finish_reasons` **and changed type from string to array**. A query filtering on the old string value breaks in two ways.

Confirm each renamed series is emitting under its new label, then update saved panels and alerts.

## Phase 8 — rollback

Deploy `0.48.2` over `0.48.3` against the same database. It must start cleanly and run a chat.

The `dag_nodes.trace_id` column stays behind; the old binary ignores it. There is no down-migration and none is needed. If the old binary fails to boot against the migrated DB, that is a **stop-the-release** finding.

## What to report back

For each phase: pass / fail / not-run, with the observed value where a number or string is involved. Specifically worth capturing even on success:

- The GENERATION count and total cost from phase 3, next to the v0.48.2 baseline.
- Whether `gen_ai.agent.name` changed anything about how Langfuse typed or priced the generation.
- Anything where the UI and Langfuse disagree about the same run.

Do not fix anything you find. Report it with what you ran and what you saw.

## Known and expected — not bugs

- `quack.compaction` is a disconnected trace root.
- The deep link is trace-level; every node on a run shares one link.
- Secrets in prose are not redacted; only key-name matches are.
- Content over 8 KiB is truncated on the span but not in the UI.
- A delivered steer never appears in `gen_ai.input.messages` (blocked on #1029).
- `gen_ai.workflow.name` holds a plan UUID rather than a human-readable name.
